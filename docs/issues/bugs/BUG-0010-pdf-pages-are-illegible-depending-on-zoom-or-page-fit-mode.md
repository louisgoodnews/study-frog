## Context
With certain PDF files, depending on the zoom setting or page fit mode of the viewer (especially after opening the sidebar thumbnail list or switching between FitWidth and FitPage), pages become completely blurred, distorted, and illegible.

## Description
Root cause analysis:
In `crates/studyfrog-ui/src/view/pdf_page.rs`, `picture_for` returns `exact.or(same_page)`. When a high-resolution render is in-flight, `same_page` returns the 250-milli thumbnail generated by the sidebar. `texture(ui.ctx(), &view.path, key, &px)` is then called with the target `key` (e.g. scale 1250) but passing the low-resolution thumbnail pixels.
In `crates/studyfrog-ui/src/view/pdf_texture.rs`, `texture` creates and caches an `egui::TextureHandle` under `texture_id(path, key)`. When the high-res render completes, `texture()` checks `ctx.data`, finds the existing cached texture handle (which holds the blurry thumbnail), and reuses it indefinitely. The UI then stretches this tiny raster over the full screen, rendering glyphs completely illegible.

Steps to reproduce:
1. Open a PDF document with small text or dense diagrams.
2. Open the sidebar thumbnail list (triggering thumbnail renders at 250 milli-scale).
3. Select "Fit to Width" or change the zoom level.
4. Notice the displayed page content is permanently rendered from the upscaled low-resolution thumbnail, appearing severely blurred and illegible.

## Acceptance Criteria
- [ ] PDF pages render sharp and legible text across all zoom levels and page fit modes (fit width, fit height, original size)
- [ ] Fallback pictures for in-flight renders do not overwrite or poison the texture handle of the target high-resolution scale
- [ ] Resizing the window or changing fit modes reliably updates textures to the correct physical pixel density

## Design Notes
Crate touchpoints:
- In `crates/studyfrog-ui/src/view/pdf_page.rs`: separate the requested target resolution key from the actual picture pixel dimensions. Do not register a low-resolution fallback picture under the high-resolution key's ID.
- In `crates/studyfrog-ui/src/view/pdf_texture.rs`: key texture handles by `(path, page, px.width, px.height)` rather than requested scale, or invalidate the cache entry when higher-resolution pixels arrive.
- Release target: version 0.5.0 (Phase M12).
