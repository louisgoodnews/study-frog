## What the attached file may be
Read the whole attached file before you write anything. Use only what is in it; do not add facts from memory.
- **Ordinary text, Markdown or text copied from a PDF:** take the concepts, definitions, facts, steps, dates and examples. If PDF text is broken (words split by line breaks, page numbers, headers), repair it silently and ignore headers, footers and page numbers.
- **Source code (python, r, rust, php, java, cpp and the like):** do not copy the code wholesale. Take what each function, class or module is for, its inputs and outputs, the rules it enforces, and the edge cases and errors it handles. Short snippets (a few lines) may go in a Markdown code fence with the language, inside a quoted cell.
- **Data and configuration (toml, json, html, csv, tsv):** take the meaning of each field or tag, the structure (what contains what), the allowed values and the relations. Do not turn rows of data into one item each unless the file is a list of facts to learn.
- **Several files:** treat them as one subject and say in `tags` which file an item came from only when that helps.
