## 1. Executive Summary & Strategic Vision

With the completion and deployment of **StudyFrog v0.9.0**, the platform established an unprecedented local-first foundation:
- An embedded offline Small Language Model (SLM) assistant powered by Qwen2.5-1.5B via an autonomous sidecar process.
- 21-parameter FSRS-6 Adam optimization and metacognitive calibration.
- The 2D spatial FrogCanvas concept board and high-performance PDF sub-page precision cropping.

**StudyFrog v1.0.0** represents the watershed transition from a specialized flashcard and review tool into a **complete, evidence-based academic workstation**. Inspired by real-world learning science, student cognitive workflows, and the founder's proven methodology of building interactive testing laboratories for professional examinations, v1.0.0 addresses the full cycle of higher education:
1. Planning coursework, homework, and deadlines alongside lecture timetables.
2. Interacting through a clean, light, distraction-free interface with universal import and comprehensive guidance.
3. Leveraging cognitive telemetry and local SLM verification to model the learner's individual memory dynamics.
4. Mastering complex university domains through diagnostic case scenarios, procedural math drills, and realistic simulated mock exams ("Altklausuren").

### Pillar 1: Academic Coursework & Homework Operations (EPIC-056)
Integrates university assignments, problem sets, and readings directly with the existing calendar, timetable lectures, and spaced repetition schedules. Students receive proactive lead-time notifications (24h, 2h, 15m) before deadlines and maintain a unified academic planner.

### Pillar 2: Human-Centered Ergonomics & Cognitive Breathing Room (EPIC-057)
Resolves interface density and cognitive overload identified in the GUI design audit. Consolidates fragmented import buttons into a single **Universal Import Hub** with intelligent file format detection, equips all 14 top-bar icons and tools with rich hover tooltips and keyboard shortcut cues, and fixes layout collisions.

### Pillar 3: Accessible Internal Scripting & FrogScript Wiki (EPIC-058)
Unlocks the power of StudyFrog's internal scripting environment for everyday users. Adds an in-GUI interactive FrogScript documentation browser, standard library reference, syntax cheatsheet, and a 1-click runnable cookbook for automation scripts.

### Pillar 4: Gamified & Multi-Modal Memory Conditioning (EPIC-059)
Complements standard SRS and open-face matching with classic **Memory Mode**: face-down flashcard pairs (front and back) that students uncover two at a time to reunite pairs against the clock. Features responsive grid layouts, card back styling, and time-attack countdown challenges.

### Pillar 5: Persistent Cognitive Profiling & The University Exam Lab (EPIC-060 – EPIC-063)
Transforms StudyFrog into an adaptive, self-tuning cognitive system:
- **Persistent Cognitive Profiling (EPIC-060)**: Logs millisecond latency, dwell times, and semantic deviation scores in SQLite to model individual forgetting curves and calculate personal learning velocity.
- **Case-Study Decision Matrices (EPIC-061)**: Supports complex scenario vignettes (e.g. Psychological Assessment) where students select diagnostic procedures and draft free-text justifications evaluated by the local SLM across multiple rubric criteria.
- **Psychometric Formula Drills (EPIC-062)**: Generates infinite synthetic calculation exercises ($s_e$, confidence intervals, standard score transformations) with step-by-step intermediate calculation error diagnosis.
- **Altklausur Mock Exam Lab (EPIC-063)**: Synthesizes realistic, timed mock exams from lecture slides, computes weighted scores, and converts results directly into the German university grading scale ($1.0 \dots 5.0$).

## 5. Architectural Invariants & Quality Standards

All implementations across v1.0.0 must adhere strictly to StudyFrog's inviolable architectural principles:
1. **Invariant P1 (Zero Inherent Impls)**: All domain logic, state machines, and calculations must reside in pure free functions. Types remain pure data carriers.
2. **Invariant P6 (File Size Limit)**: Every Rust source file (`.rs`) must strictly maintain $\le 250$ lines of code.
3. **Invariant P8 (Local-First Data Sovereignty)**: All study materials, notes, telemetry, and settings remain plain human-readable files and local SQLite records in the user's vault. Zero telemetry leaves the machine.
4. **Invariant P9 (Safe Rust)**: Strict `#![forbid(unsafe_code)]` enforced across all crates.
5. **Theme Integrity**: Use only palette color tokens from `palette_of(ui)` (never raw RGB literals).
